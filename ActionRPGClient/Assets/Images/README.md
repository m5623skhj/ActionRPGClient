# 이미지 디렉터리

캐릭터 스프라이트 시트, 마을 배경, 이펙트 이미지를 보관합니다.

- 캐릭터·이펙트처럼 논리적 ID로 찾는 이미지는 `Assets/Data/assets.ini`의 `[Images]`에 상대 경로를 등록합니다.
- 마을 배경은 맵 JSON의 `images[].asset`에 `Images/Towns/파일명.png`처럼 `Assets/` 기준 상대 경로를 기록합니다. 이 이미지는 `[Images]` 등록이 필요하지 않습니다.

플레이어 스프라이트 시트 구성은 `Assets/Data/animations.ini`에서 지정합니다. 프레임은 왼쪽에서 오른쪽으로, 다음 행은 위에서 아래로 읽습니다. 두 행의 여백이 서로 다르면 `first_row_ratio`로 행의 분할 위치를 조정할 수 있습니다.

## 아이템 아이콘의 크기 일관성

- 화면상 아이템 슬롯·아이콘 표시 크기·여백은 아이템 퀵슬롯 규격을 최우선으로 한다. 인벤토리·장비창도 그 규격에 맞춰 축소·통일하며, 개별 아이템에만 다른 확대 배율을 적용하지 않는다.
- 실제 화면 표시 수치는 클라이언트 담당이 [COMBAT_CLIENT.md](../../COMBAT_CLIENT.md)와 [TOWN_NETWORK.md](../../TOWN_NETWORK.md)에 확정하는 공통 표시 규격을 따른다. 그래픽 지침에 화면 수치를 별도로 중복 기록하지 않는다.
- 기존 `Items/` 아이콘의 원본은 64×64 RGBA PNG다. 원본 픽셀 크기와 화면 표시 크기를 구분하고, 원본 캔버스의 공통 안전 영역·중심 정렬·투명 여백을 유지한다. 종횡비를 보존하며 아이템별로 투명 여백을 잘라내 확대하거나 캔버스를 늘려 표시 크기를 맞추지 않는다.
- 아이템·스킬 아이콘의 퀵슬롯·인벤토리·장비·스킬 트리·상세·드래그 표시는 클라이언트가 확정한 공통 아이콘 표시 크기를 따르고, 모든 뷰에서 같은 축소 필터를 사용한다. 원본 대비 비정수 배율의 표시 축소를 허용하되, 원본 캔버스에서 최종 표시 영역으로 한 번만 축소하며 중간 크기의 PNG 사본은 만들지 않는다. 도트가 흐려지지 않도록 표시 좌표·영역을 정수 픽셀에 맞추고, 항목별 자르기·확대로 작은 크기의 세부 손실을 보정하지 않는다.

## 마을 그래픽 표시 규격

- 현재 PlayerIdle의 192×192 표시에서 보이는 사람 높이는 약 185 월드 단위다. 마을 문·벽돌·바닥돌의 비율은 이 실제 실루엣을 기준으로 검토한다.
- 기본 마을 바닥 타일은 512×512, 건물 캔버스는 512×768이며 최종 PNG 1픽셀을 월드 1단위로 배치한다. 투명 여백을 포함한 캔버스를 유지한다.
- 제작 원본은 최종 소비 크기 이상이어야 한다. 원본 확대를 금지하며, 종횡비를 유지한 균일 축소·내용을 보존하는 크롭·투명 패딩으로만 규격을 맞춘다.
- 반영 전에 최종 PNG를 1:1 정적 화면에서 실제 캐릭터와 같은 발밑 기준선에 놓고 문·석재 비율과 선명도를 확인한다. 반복 바닥은 3×3 연결, 투명 자산은 외곽 잔상과 실제 알파를 확인한다.


## 흑발 여성 검사 애니메이션 제작

확정 외형은 긴 흑발, 청록 재킷, 회백색 튜닉, 짙은 회색 하의, 갈색 가죽과 은색 장식, 한손 장검이다. 기본 인체 높이는 약 170 월드 단위로 기존 남성보다 작게 유지한다. 아래 순서로 한 동작씩 제작·검토한다.

- [x] 걷기 — 4열×2행 8프레임, 10fps·0.8초 반복. 검은 일반 자세처럼 앞쪽 아래로 든다. 4프레임은 왼발 진입, 8프레임은 오른발 진입으로 양발을 교대한다.
- [x] 달리기 — 4열×2행 8프레임, 약 14.3fps·0.56초 반복. 좌우 착지·지지·무릎 전진·공중 진입을 교대하며 긴 머리가 뒤로 흩날린다.
- [x] 점프 — 도약 준비 3장·상승/정점/하강 각 1장·착지/회복 4장, 총 10프레임. 긴 머리가 상승 시 아래로, 하강 시 위로 뜨고 착지 뒤 가라앉는다.

대시 횡베기는 [player_swordswoman_dash_attack.png](Characters/player_swordswoman_dash_attack.png)다. 셀은 512×320, 기준점은 (256,296), 표시 캔버스는 384×240으로 기존과 같은 0.75배 표시 배율이다. 원화 7장에 정적 기준으로 맞춘 동일한 227/341배 축소와 평행 이동만 적용했으며, 마지막 프레임은 승인된 기본 자세를 그대로 재사용한다. 프레임 시간은 0.045·0.045·0.04·0.07·0.06·0.055·0.045·0.04초로 합계 0.40초다. 4번 프레임(`event_frame=4`, 시작 후 0.13초)을 타격 참고 시점으로 등록했고 짧은 횡베기 궤적을 해당 프레임에 포함했다. `SwordswomanDashAttack`를 등록했으며 Character4에서 기존 대시 입력과 서버 slide 상태를 대시 횡베기 표시로 연결한다. 실제 전진량·공격 판정은 서버 정의를 따른다. 미리보기의 이동량은 연출 검토용이며 게임 이동 설정에는 반영하지 않았다.

기본 4연격은 [1타 횡베기](Characters/player_swordswoman_attack_1.png)·[2타 올려베기](Characters/player_swordswoman_attack_2.png)·[3타 내려베기](Characters/player_swordswoman_attack_3.png)·[4타 회전 횡베기](Characters/player_swordswoman_attack_4.png)다. 1~3타는 각 4열×2행 8장, 4타는 5열×2행 10장으로, 셀 512×384·기준점 (256,360)·표시 캔버스 384×288을 공유한다. 각 원화 묶음의 정적 기준에 맞춰 각각 227/409·227/399·227/408·227/325배로 균일 축소했으며 프레임별 크기 보정은 하지 않았다. 1타 끝→2타 시작, 2타 끝→3타 시작, 3타 끝→4타 시작은 동일 픽셀을 재사용하고 최초·최종 자세도 승인된 기본 자세를 그대로 쓴다. 회전 베기는 오른쪽 옆모습→뒷모습→왼쪽 옆모습→정면→오른쪽으로 이어지며 머리카락이 회전을 뒤따른다. 각 타 재생 시간은 0.34·0.305·0.295·0.48초다. `SwordswomanAttack1`~`SwordswomanAttack4`를 등록했으며 `event_frame` 5·4·4·7은 타격 참고 시점이다. Character4는 X 연타를 기본 4연격으로 표시하며, 서버의 shotCount(1~4)·타별 shotSequence·위상별 shotSeconds를 사용한다. 지상 공격은 준비/타격/회복의 누적 시간으로 전체 클립을 재생하고 회복 중 이동으로 클립을 끊지 않는다.

제작 완료한 자산은 `assets.ini`와 `animations.ini`의 크기·기준점을 그대로 사용하며 캐릭터 생성/선택의 Character4(여성 검사)에 연결했다. 마을 본인과 원격 캐릭터의 외형을 구분하고, 던전은 서버 확정 characterId별 애니메이션을 사용한다. C는 점프, 공중 X는 내려베기, 달리기 중 X는 대시 횡베기다. 마을 서버의 기존 걷기 전용 이동 및 원격 걷기 표시 정책은 유지한다. 마을 공격은 표시용이며 실제 피해 판정은 던전 서버가 담당한다.

던전은 기존 v3/실시간 확장 규격을 유지하고 `combatRules.meleeDefinitions`(maxCombo=4, ground/air/dash, bodyHeight=170)의 시간을 적용한다. 재생·이동에는 공통 tempoScale=.7을 한 번 적용하고 기본 검사 공격에 총격음을 재생하지 않는다. 소비 아이템 사용의 공통 AttackFire 표시 요청은 검사의 대기 자세로 표시한다. 새 SP 스킬은 추가하지 않았다. 빌드·실행 검증은 별도 진행해야 한다.
