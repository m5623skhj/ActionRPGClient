# 던전 전투 연결

공유 원본은 서버 저장소 `Tool/PacketDefine.yml`, 실행 계약은
`ActionRPGServer/GameRoomServer/COMBAT_PROTOCOL.md`입니다. 클라이언트 생성 파일만 갱신했습니다.
기존 패킷 ID 1~6은 유지하고 7~10(행동 입력/결과, 전투 상태 요청/조각)을 추가했습니다.

## 조작 및 표시

- 던전에서 X=사격, C=점프. 이동과 독립된 행동 sequence를 연결당 1부터 사용합니다.
- 서버 Running 상태를 받은 뒤 행동을 보냅니다. 접수 응답은 타격 성공 판정이 아닙니다.
- 던전에서는 서버가 보낸 탄환만 표시합니다. V 투척과 Z 커맨드 스킬은 서버 계약에
  없으므로 던전 전투 입력으로 보내지 않습니다. 마을의 기존 입력 경로는 유지합니다.
- 서버 `combatRules`의 이동 속도·중력·점프 준비·사격 구간·피격 구간 시간을 사용합니다.
- 플레이어 HP, 몬스터 HP 바, 사망 자세, DUNGEON CLEAR를 표시합니다.
  플레이어는 현재 별도 사망 에셋이 없어 쓰러짐 마지막 자세를 유지합니다.
- 몬스터 종류별 원본 sourceRect/pivot/fps/scaleToMovement를 사용합니다.
  UseSkill animationId `attack`은 ID별 공격 시트로 연결합니다.
- 피격과 HP 0을 일반 행동보다 우선합니다. 같은 사망 스냅샷은 모션을 재시작하지 않습니다.
- 클라이언트가 피해량·피격 대상·AI·보상·게이트 잠금을 결정하지 않습니다.

## 수신 및 스레드

기존 RUDP 수신 큐를 `DungeonClient::ConsumeEvents`에서 소비합니다.
완성된 전투 JSON 이벤트만 GameWorld가 게임 스레드에서 해석·적용합니다.
한 번에 한 조각을 요청하며, 최대 768바이트·512KB를 검사합니다. 조각별 UTF-8 디코딩은 하지 않습니다.
제한 응답은 같은 snapshotId/offset을 retryAfterMs 후 재요청하고, 무효 스트림은 버립니다.
다음 스냅샷은 완료 후 200ms 이후 요청합니다. 응답 유실 재시도는 5초이며,
진행 없이 30초가 지나면 기존 연결 실패 흐름으로 종료합니다.

roomId, mapId, serverTick과 개체 ID·수치·목록 한도를 확인합니다.
이전 이동 sequence는 로컬 위치 보정만 생략하며, 같은 방의 HP·몬스터·탄환·클리어 적용은 유지합니다.
방이 바뀌면 원격 플레이어·탄환 목록을 교체합니다. 서버 목록에서 빠진 개체는 제거합니다.
몬스터와 원격 플레이어는 위치를 짧게 보간하고 높이·탄환은 최대 0.25초만 예측합니다.
수신 빈도가 낮아 순간적인 동작을 모두 표시한다고 보장할 수는 없습니다.

## 설치와 확인 범위

패킷 생성, YAML/JSON/XML·데이터 참조·생성 결과·변경 diff를 정적으로 확인합니다.
게임 빌드·프로그램 실행·실제 던전 전투 테스트·커밋은 수행하지 않습니다.
이 소스 변경은 기존 exe에 반영되지 않습니다. 양쪽 소스를 추후 빌드해야 하며,
실행 데이터 설치 상태와 실제 플레이 확인은 별도로 구분해야 합니다.
