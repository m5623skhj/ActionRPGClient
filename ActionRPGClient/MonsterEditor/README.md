# Monster AI Editor

몬스터별 상태·행동·조건을 그래프로 편집하고 JSON으로 저장하는 로컬 도구입니다.
편집기 데이터, 정적 검사기, 화면 코드를 분리했습니다.

## 빠른 시작과 문서 안내

아래 프로젝트·실행 파일 경로는 `ActionRPGClient.slnx`가 있는 클라이언트 프로젝트 폴더 기준입니다.

| 항목 | 안내 |
|---|---|
| 바로 열기 | [index.html](index.html)을 Edge/Chrome에서 열기; 서버·npm 설치 불필요 |
| Windows 런처 | [MonsterEditor.vcxproj](MonsterEditor.vcxproj), `artifacts/bin/x64/Debug/MonsterEditor.exe` (Release도 같은 구조) |
| 시작 예제 | [Example.ai.json](Example.ai.json)을 직접 불러오기; 새 문서는 빈 그래프로 시작 |
| 작업 흐름 | 생성·불러오기 → 몬스터/상태/연결/스킬·동작 편집 → 작업 저장 → 정적 검사 → AI 승인·별도 스냅샷 저장 → 별도 등록·설치 |
| 상세 안내 | 아래 데이터 형식·행동/조건·정적 승인·서버/클라이언트 등록 절에서 schemaVersion 1과 연동 범위 설명 |

일반 작업 저장과 승인 스냅샷은 별개입니다. 승인 버튼은 게임 AI나 타격을 실행하지 않고 정적 검사 결과를 기록합니다.
이미지·전투 프로필·카탈로그 등록과 설치는 자동 처리하지 않습니다.
플레이어 스킬 제작은 별도 [SkillEditor 안내](../SkillEditor/README.md)를 따릅니다.


## 열기

- 이 폴더의 `index.html`을 브라우저에서 엽니다.
- 또는 Visual Studio 솔루션에서 `MonsterEditor` 프로젝트를 빌드한 뒤
  `artifacts/bin/x64/Debug/MonsterEditor.exe`를 실행합니다.
- 실행 프로젝트는 실행 파일 옆 `MonsterEditor/index.html`을 OS의 HTML 연결 프로그램으로 엽니다.
  HTML 파일이 코드 편집기에 연결되어 있다면 브라우저로 직접 열거나 연결 프로그램을 변경합니다.
- 외부 서버, npm, CDN, 인터넷 연결이 필요하지 않습니다.
- 브라우저의 파일 선택·쓰기 API를 사용할 수 있으면 파일을 직접 열고 덮어씁니다.
  API를 사용할 수 없으면 일반 파일 선택과 JSON 다운로드를 사용합니다.
  다운로드 경로는 브라우저 설정을 따르며, 도구는 다운로드 완료를 확인할 수 없습니다.
  다운로드 방식에서는 저장하지 않은 변경 경고를 유지합니다.

`Example.ai.json`은 대기 → 추적 → 공격 → 추적, 추적 → 복귀 → 대기의 순환 예제입니다.
처음 실행할 때와 **새 문서**는 몬스터·스킬·동작이 없는 빈 문서로 시작합니다.
예제를 사용하려면 해당 파일을 직접 불러옵니다. 예제의 이미지 ID는 실제 게임 에셋 등록을 의미하지 않습니다.
빈 문서도 작업 파일로 저장하고 불러올 수 있으며, 몬스터를 추가하기 전에는 AI 승인을 할 수 없습니다.

## 편집

1. 왼쪽에서 몬스터를 선택하거나 추가·복제합니다.
2. **＋ 상태**로 노드를 추가합니다. 오른쪽에서 상태 이름과 행동을 편집합니다.
3. 노드 오른쪽 포트를 클릭한 뒤 대상 노드를 클릭해 연결합니다.
   선택한 상태에서 **연결** 버튼으로 시작해도 됩니다. 자기 자신으로의 연결도 지원합니다.
4. 연결선을 선택해 조건, 전환 시점, 우선순위를 편집합니다.
5. 스킬·동작 목록에서 정의를 추가하면 **스킬 사용**·**동작 재생** 행동에서 선택할 수 있습니다.
6. **JSON 저장**으로 작업 중 문서를 저장하거나, **AI 승인 · 저장**으로 정적 검사 후 승인 파일을 저장합니다.

노드는 드래그로 배치하고, 빈 공간 드래그로 화면을 이동합니다.
휠로 확대·축소하고 **전체 보기**로 그래프를 맞춥니다.
`Delete`는 선택한 노드 또는 연결을 삭제합니다.
`Ctrl+S`는 저장, `Ctrl+O`는 불러오기, `Esc`는 연결 취소입니다.

노드 ID를 바꾸면 해당 몬스터의 시작 노드와 연결 참조를 함께 바꿉니다.
스킬·동작 ID를 바꾸면 문서 전체의 행동·조건 참조를 바꿉니다.
삭제한 정의를 사용하는 참조는 자동으로 다른 스킬로 대체하지 않고 검사 오류로 표시합니다.

## 데이터 형식

루트에는 `schemaVersion=1`, `documentId`, `skills`, `motions`, `monsters`, `approval`을 둡니다.

- 몬스터: `id`, `name`, `maxHp`, `ai`
- AI: `initialNodeId`, `nodes`, `edges`
- 노드: `id`, `label`, `position{x,y}`, `action{type,parameters}`
- 연결: `id`, `from`, `to`, `priority`, `trigger`, `condition`

ID는 영문자로 시작하는 1~64자의 영문·숫자·밑줄·마침표·하이픈입니다.
거리·위치는 월드 단위, 시간은 초, HP 비율은 현재 HP / 최대 HP입니다.
노드 위치는 편집 화면의 배치용이며 실제 몬스터의 위치가 아닙니다.

### 행동

| type | parameters | 완료 규칙 |
| --- | --- | --- |
| `Wait` | `seconds` > 0 | 지정한 시간을 실제로 소비하면 완료 |
| `MoveToTarget` | `stopDistance` ≥ 0, `run` | 대상의 정지 거리 안에 도착하면 완료 |
| `ReturnToSpawn` | `arrivalDistance` ≥ 0 | 생성 위치에 도착하면 완료 |
| `UseSkill` | `skillId` | 실제 스킬을 시작하고 동작 시간이 지난 뒤 완료 |
| `PlayMotion` | `motionId` | 실제 동작 시간이 지난 뒤 완료; 반복 동작은 완료하지 않음 |

스킬 정의는 `id`, `label`, `animationId`, `durationSeconds`,
`cooldownSeconds`, `minRange`, `maxRange`, `hitType`을 가집니다.
피격 유형은 `Normal` 또는 `Airborne`입니다.

동작 정의는 `id`, `label`, `animationId`, `durationSeconds`, `loop`를 가집니다.
스킬·동작 시간을 0으로 지정할 수 없습니다.

### 조건

일반 조건은 `{ "type": "...", "parameters": { ... } }`로 표현합니다.

| type | parameters | 의미 |
| --- | --- | --- |
| `Always` | 빈 객체 | 항상 참 |
| `HasTarget` | 빈 객체 | 유효한 대상 있음 |
| `TargetLost` | 빈 객체 | 유효한 대상 없음 |
| `TargetInRange` | `distance` | 대상이 있고 거리가 지정 값 이하 |
| `TargetOutOfRange` | `distance` | 대상이 있고 거리가 지정 값 초과 |
| `SkillReady` | `skillId` | 스킬 쿨다운·대상·사용 조건 충족 |
| `StateTimeAtLeast` | `seconds` | 현재 상태의 실제 경과 시간이 지정 값 이상 |
| `HealthRatioAtMost` | `ratio` | HP 비율이 0~1 범위의 지정 값 이하 |
| `AtSpawn` | `distance` | 생성 위치와의 거리가 지정 값 이하 |

복합 조건은 `{ "type": "All|Any|Not", "children": [...] }`입니다.
`All`은 AND, `Any`는 OR이고, 둘 다 한 개 이상의 자식이 필요합니다.
`Not`은 자식이 정확히 하나여야 합니다.

### 전환 시점과 실행 계약

| trigger | 의미 |
| --- | --- |
| `OnUpdate` | 현재 상태에 진입한 업데이트에서는 실행하지 않음. 다음 업데이트부터 검사 |
| `AfterAction` | 현재 행동이 완료된 후 조건을 검사 |
| `Immediate` | 조건을 만족하면 같은 업데이트 안에서도 다음 상태로 전환 가능 |

실행기는 현재 상태에서 **시점과 조건을 모두 만족하는 연결** 중 `priority`가 가장 작은 것을 선택해야 합니다.
같은 출발 상태의 우선순위는 중복될 수 없습니다.
상태에 들어갈 때 행동과 상태 경과 시간을 초기화하고,
즉시 전환 중에는 경과 시간을 늘리지 않습니다. 실제 업데이트 시간만 경과 시간에 더합니다.
조건은 활성 상태의 업데이트마다 다시 평가하므로 경과 시간 조건으로 지연을 줄 수 있습니다.

`AfterAction`은 행동 시작 실패를 완료로 처리하지 않습니다.
스킬이 준비되지 않았다면 실행기는 사용 가능 시점까지 기다리거나 `OnUpdate` 전환을 처리합니다.
피격 등 외부 중단은 공통 캐릭터 상태에서 처리하며 AI의 성공 완료 신호로 바꾸지 않습니다.
이 규칙과 정의의 동작 시간 하한을 실행기가 지켜야 정적 순환 검사의 판단이 유효합니다.
실행기를 추가할 때는 비정상 데이터에 대비한 업데이트당 전환 횟수 제한도 함께 적용해야 합니다.

HP ≤ 0이면 공통 사망 처리에서 AI를 종료합니다.
죽음 노드나 HP 0 전환을 모든 AI 그래프에 반복해서 넣을 필요는 없습니다.

## 정적 검사와 승인

**정적 검사**는 문서 전체의 모든 몬스터·스킬·동작을 검사합니다.

오류로 승인 차단:

- 지원하지 않는 버전·행동·조건·필드
- 중복 ID, 시작 노드 누락, 연결의 출발·도착 노드 누락
- 시작 노드에서 구조적으로 도달할 수 없는 상태
- 없는 스킬·동작 참조, 잘못된 수치·범위·자료형
- 같은 상태의 우선순위 중복, 같은 시점의 항상 전환이 뒤의 연결을 가리는 경우
- 완료되지 않는 반복 동작에서 `AfterAction` 사용
- 시간을 소비하지 않고 같은 업데이트 안에서 반복될 수 있는 순환

정상적인 순환은 오류가 아닙니다.
`OnUpdate`를 포함하거나 실제 대기·동작 시간을 소비하는 순환은 허용합니다.
검사기는 즉시 연결과 시간 지연이 보장되지 않는 완료 연결만 따로 모아 순환을 탐색합니다.
대상 거리·HP·쿨다운 같은 외부 조건의 상호 배타성은 증명하지 않으므로
즉시 순환 가능성을 보수적으로 오류 처리할 수 있습니다.
이때 다음 업데이트 전환 또는 실제 경과 시간 조건으로 진행을 제한합니다.

나가는 연결이 없는 상태는 의도적인 정지일 수 있어 경고로 표시하며 승인 자체는 허용합니다.
시간 조건의 비현실적인 길이, 모든 외부 조건 조합의 만족 가능성, 실제 전투 품질,
경로 탐색 성공, 애니메이션 파일 존재, 스킬 효과 구현, 서버 판정은 검사하지 않습니다.
승인은 이러한 실행 결과를 보장하는 인증이 아닙니다.

**AI 승인 · 저장**은 검사 오류가 없을 때만 `approval.status=approved`와
검사기 버전·시각·검사 범위·경고 개수를 기록해 별도의 `.approved.ai.json` 파일 저장을 요청합니다.
일반 저장은 작업 중인 오류를 가진 문서도 저장할 수 있습니다.
승인 파일은 별도의 스냅샷이며 이후 일반 저장의 덮어쓰기 대상으로 연결하지 않습니다.
승인 파일을 불러온 뒤 일반 저장할 때도 새 작업 파일의 위치를 선택합니다.
수정하면 승인 기록을 해제합니다. 승인된 파일을 다시 불러와도 기존 기록을 신뢰하지 않고
현재 데이터로 다시 검사·승인하도록 합니다.

현재 GameRoomServer의 MonsterDefinition 로더는 schemaVersion 1 문서와 그래프를 다시 검사합니다.
approval.status만으로 로딩 여부를 결정하지 않으며, 내용이 유효한 초안도 로딩할 수 있습니다.
AI 실행은 GameRoomCombat.cpp에서 개체별로 처리하며 한 틱의 전환을 최대 64회로 제한합니다.
편집기의 승인 버튼은 이 실행 결과나 게임 플레이를 확인하지 않습니다.

## 확장과 제한

여러 스킬·동작을 추가하고 각 상태에서 ID로 선택할 수 있습니다.
다단계 패턴은 준비 동작 → 스킬 → 회복 동작처럼 여러 상태를 연결해 표현합니다.
새 행동·조건 종류에는 `model.js`의 정의·검증 규칙과 게임 실행기의 해당 구현이 필요합니다.
화면의 파라미터 입력은 정의 목록에서 생성하므로 일반 숫자·불리언·스킬·동작 참조 필드는 재사용됩니다.

문서당 몬스터 최대 256개, 몬스터당 노드 최대 512개·연결 최대 2048개,
스킬·동작 목록 각각 최대 2048개를 지원합니다.
조건은 연결당 최대 깊이 8, 항목 128개까지 지원하고 파일 불러오기는 최대 5MB입니다.
이 한도는 과도한 중첩과 큰 그래프의 편집·검사 비용을 제한하기 위한 것입니다.

편집과 검사는 브라우저의 단일 이벤트 루프에서 수행하고 파일 처리 중에는 편집을 잠급니다.
이 도구는 서버의 살아 있는 몬스터 상태나 공유 메모리를 변경하지 않습니다.
편집기에는 움직임·전투 시뮬레이터와 아이템 드랍 편집 UI가 없습니다.
서버에는 AI 실행과 기본 공격·피격 처리가 연결되어 있지만 드랍·보상 지급은 아직 구현하지 않았습니다.

## 파일 구성

- `index.html` / `editor.css`: 화면과 스타일
- `editor.js`: 그래프 조작·속성 편집·파일 입출력·승인 흐름
- `model.js`: 데이터 정의·빈 문서 생성·정적 검사
- `Example.ai.json`: 순환 그래프 예제
- `Main.cpp`: Windows 실행 파일의 로컬 편집기 열기
- `MonsterEditor.vcxproj`: 독립 실행 프로젝트와 편집기 파일 복사

브라우저 파일 처리 구현의 참고 문서는
[Chrome File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)입니다.

## 순환 예제와 오류 해결

`Example.ai.json`을 열어 대기 → 추적 → 공격 → 추적, 추적 → 복귀 → 대기 연결을 확인합니다.
`Wait.seconds`를 양수로 두고, 추적의 거리 조건과 공격의 SkillReady를 지정합니다.
공격은 UseSkill이 완료된 뒤 AfterAction으로 추적 또는 회복 상태로 돌아가도록 편집합니다.
**정적 검사**에서 오류를 해소하고 일반 작업 JSON을 저장한 뒤 **AI 승인 · 저장**으로 별도 스냅샷을 출력합니다.
승인은 문서의 정적 계약 확인이며 실행·이미지 재생·타격 성공 확인이 아닙니다.

즉시 순환 오류는 Immediate 연결만 반복되는지 확인하고 실제 Wait/StateTimeAtLeast 또는 OnUpdate로 시간 진행을 확보합니다.
참조 오류는 스킬·동작 정의와 행동/조건의 ID를 맞추고, 도달 불가 오류는 initialNodeId에서 모든 노드까지 연결되는지 확인합니다.
새 스킬·드랍 필드를 임의로 JSON에 추가하면 지원하지 않는 필드로 거절됩니다. 확장에는 모델·검사기·서버 계약 변경이 필요합니다.

## 서버·클라이언트 등록

1. AI 문서를 서버 `ActionRPGServer/GameRoomServer/Data/Monsters/`에 두고 MonsterCatalog.json의
   `{dataId, definitionFile, monsterId}`로 숫자 배치 ID와 문서의 문자열 몬스터 ID를 연결합니다.
2. 스킬의 damage/hitSeconds/reachHeight와 이동·감지·피격 크기는 서버 `Data/Combat.json`에 별도로 정의합니다.
   MonsterEditor의 minRange/maxRange/cooldown/duration만으로 실제 피해량이 완성되지 않습니다.
3. 클라이언트 `Assets/Data/monsters.json`의 같은 dataId/monsterId, 모션 메타데이터·PNG·renderHeight를 맞춥니다.
   `animationId`는 외형 모션 참조이며 AI 노드 ID와 별개입니다.
4. 원본 저장은 실행 파일 옆 데이터 설치와 다릅니다. 서버 시작 시 로딩하는 데이터와 클라이언트 Assets를 갱신해야 합니다.

현재 ID 1 Dummy는 대기하고, ID 2 녹슨 갑옷병·ID 3 수호자는 감지·추적·공격·회복·귀환 패턴이 연결되어 있습니다.
신규 등록은 편집기가 자동으로 수행하지 않습니다. DungeonEditor 팔레트도 현재 Data ID 1/2/3만 지원합니다.
편집기 불러오기 상한은 5MB지만 서버 AI 정의 파일은 4MB 이하, 참조 정의 합계는 64MB 이하입니다.
