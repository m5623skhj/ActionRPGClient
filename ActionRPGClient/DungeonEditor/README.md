# Dungeon Map Editor

## 실행

이 폴더의 `index.html`을 Edge 또는 Chrome에서 엽니다. 인터넷, npm 설치, 별도 서버가 필요하지 않습니다.
처음에는 빈 던전으로 시작합니다.
Visual Studio의 `DungeonEditor` 프로젝트를 빌드하면 `artifacts/bin/x64/Debug/DungeonEditor.exe`로도 열 수 있습니다.
HTML이 텍스트 편집기에 연결되어 있다면 브라우저에서 직접 여세요.

## 기본 작업 순서

1. 왼쪽 **＋**로 방을 추가하고 ID·이름을 정합니다. 던전 속성에서 최초 입장 방과 최대 인원을 지정합니다.
2. **방 구성**에서 방을 드래그하고 **방 연결**을 눌러 목적지 방을 클릭합니다.
   연결된 방은 상하좌우로 한 칸씩 붙여 배치합니다. 연결 선을 선택하면 양방향 여부를 바꿀 수 있습니다.
3. 방을 더블 클릭해 **방 내부**를 엽니다. **이미지 추가**로 배경을 넣고 위치·크기를 수정합니다.
   **이미지에 월드 영역 맞춤**으로 표시 영역을 맞추거나 경계를 직접 입력합니다.
4. **이동 가능 W** / **진입 불가 B**로 다각형을 그립니다. 좌클릭으로 점을 추가하고 Enter로 완성합니다.
5. 최초 입장 방에서 **입장 위치 P**로 최대 인원만큼 발 위치를 지정합니다.
6. 모든 방에 **워프 도착점 E**를 배치하고 기본 도착점을 선택합니다. 여러 도착점을 만들 수 있습니다.
7. **게이트·발판 Z**로 방 경계 안쪽에 이동 영역을 그립니다. 연결·실제 출구 방향·목적지 도착점을 지정합니다.
   표시 형태는 게이트 또는 발판이며 기본 이미지나 직접 불러온 이미지를 사용할 수 있습니다.
   양방향 연결은 양쪽 방에 출구를 만들어야 합니다.
8. **특수 오브젝트 O**로 기본 오브젝트를 추가하고 이미지·종류·JSON 속성을 설정합니다.
9. 왼쪽 **Dummy · Data ID 1** 이미지를 방 내부로 드래그해 몬스터를 배치합니다.
   클릭하거나 **Dummy M** 모드를 선택한 뒤 발 위치를 클릭해도 됩니다.
   선택 모드에서 이미지 드래그, 발 좌표·방향 수정, 복제·삭제가 가능합니다.
10. **작업 저장**으로 JSON을 저장합니다. **정적 검사**를 확인하고 **던전 · 미니맵 출력**으로 ZIP을 내보냅니다.

걷기·달리기 속도는 방 속성과 저장·출력 데이터에 포함하지 않습니다.
이동 속도는 게임에서 플레이어·몬스터 정보로 관리할 항목입니다.

## 미니맵과 게이트

자동 미니맵은 이름 없이 작은 일반 방 아이콘과 보스 해골 아이콘, 연결선으로 표시합니다.
초록 점은 최초 입장 방입니다. 연결선 끝은 실제 게이트·발판의 연결 지점입니다.
게이트는 금색, 발판은 하늘색이며 단방향 연결에는 화살표가 표시됩니다.
미니맵의 방을 클릭하면 내부 편집 화면으로 이동합니다.
큰 **방 구성** 화면에서는 편집을 위해 방 ID도 표시합니다.

```text
□—□—□—[보스]
    |
□—□
```

A가 (0, 0), B가 (1, 0)에 있다면:

- A → B: A의 **오른쪽** 출구 → B의 **왼쪽** 도착점
- B → A: B의 **왼쪽** 출구 → A의 **오른쪽** 도착점
- A의 왼쪽 게이트가 B로 이어지거나 B의 오른쪽 도착점으로 들어가면 출력 오류입니다.

출구 영역 전체와 도착점은 해당 방향의 **경계 구간**에 있어야 합니다.
깊이는 해당 축의 방 크기 20%와 128px 중 작은 값입니다.
1280×720 방에서 오른쪽 구간은 X=1152~1280, 왼쪽 구간은 X=0~128입니다.
발 영역이 이동 가능한 지형 안에 있도록 경계선에서 안쪽으로 떨어뜨려 배치하세요.
표시 이미지의 중심은 워프 영역 안에 있어야 합니다. 영역 전체를 드래그하면 표시 이미지도 이동합니다.
도착점은 워프 영역 밖에 두어 즉시 재이동을 피하세요.

연결된 방은 한 칸씩 인접해야 합니다. 대각선·겹침·멀리 떨어진 연결은 출력 오류입니다.
방 배치를 바꾸면 게이트와 도착점의 방향도 함께 맞춰야 합니다.
상하좌우 연결로 이루어진 순환 던전은 허용합니다.

## 특수 오브젝트

- ID, 이름, 종류 ID, 표시 위치·크기와 이미지
- 종류 예: `generic`, `chest`, `switch` (직접 입력)
- 추가 속성 JSON 예: `{"interactionId":"Door01","enabled":true}`
- 기본 표시 또는 사용자 이미지, 선택·드래그·복제·삭제와 저장·불러오기

현재는 배치와 메타데이터 출력까지 지원합니다.
종류·속성이 실제 상호작용이나 충돌·드랍 동작을 실행하지는 않습니다.
게임 기능을 추가할 때 해석하면 됩니다.

## 조작

- 선택 모드에서 이미지·위치·영역·오브젝트 드래그
- 영역 선택 후 꼭짓점 드래그 또는 오른쪽 좌표 입력
- 겹친 요소는 왼쪽 **방의 요소**에서 선택
- 가운데 버튼 / Space+좌클릭 드래그: 화면 이동
- 휠: 확대·축소, F: 전체 보기
- V: 선택, W: 이동 가능, B: 진입 불가, P: 입장 위치, E: 도착점, Z: 게이트·발판, O: 특수 오브젝트
- Enter: 영역 완성, Backspace: 마지막 점 취소, Esc: 작성 중인 영역·연결 취소
- Delete: 선택 요소 삭제, Ctrl+S: 작업 저장

방 복제는 배경·지형·입장 위치·도착점·특수 오브젝트를 복사합니다. 연결과 게이트는 새 방에서 지정합니다.
방 삭제는 관련 연결·게이트도 삭제합니다. 도착점 삭제로 남은 참조는 정적 검사 오류로 표시합니다.

## 저장과 출력

작업 JSON(`*.dungeon-project.json`)은 `schemaVersion: 3`입니다.
이미지 원본을 base64로 포함하므로 원본 파일이 없어도 다시 편집할 수 있습니다.
이전 version 1/2도 불러옵니다. 몬스터 목록은 비워 두고 서버 던전 Data ID는 1로 초기화합니다. 속도 필드를 제거하고 게이트 표시·방향을 변환합니다.
경계에 있는 기존 게이트만 실제 위치로 방향을 추정하며 나머지는 직접 지정해야 합니다.
변환 후 정적 검사하고 작업 저장하세요.
미완성 상태나 빈 던전도 저장할 수 있지만 작성 중인 다각형은 완성 또는 취소해야 합니다.

출력 ZIP:

```text
Dungeon.json                          던전 구성, 입장 슬롯, 연결·게이트, 미니맵 좌표 (version 3)
Maps/<DungeonId>_<RoomId>.json         속도 없는 던전 방 (version 5, format DungeonRoom)
Assets/Images/Dungeons/<DungeonId>_*   배경, 게이트·발판·특수 오브젝트 이미지
Assets/Images/Monsters/dummy.png       기본 Dummy 이미지 (64×96, 투명 배경)
Minimap.svg / Minimap.png             간소화된 미니맵 (투명 배경)
Icons/normal.svg / Icons/normal.png    일반 방 아이콘
Icons/boss.svg / Icons/boss.png        보스 방 아이콘
```

방 JSON에는 월드·이미지·이동 영역·입장·도착점·`transitionZones`·`objects`·`monsters`가 들어갑니다.
`transitionZones`는 `connectionId`, `direction`, `visual`과 `MapTransfer` 목적지를 포함합니다.
기본 게이트·발판·오브젝트 이미지를 생성해 ZIP에 포함합니다.
`images`에도 표시 이미지를 반영합니다. 런타임에서 `objects`·`visual`을 별도로 그린다면 중복 표시를 피해야 합니다.
이미지 경로는 실행 폴더 `Assets` 기준 상대 경로입니다.

`Dungeon.json` 연결에는 출발·도착 방향과 해당 워프 ID가 들어갑니다.
`minimap.connections`의 `fromPort`·`toPort`는 연결선 끝 좌표입니다.
`minimap.rooms`의 중심 좌표로 게임에서 현재 방 표시를 그릴 수 있습니다.
최대 한 변은 4096px이며 배치가 넓으면 비례 축소됩니다.

파일 쓰기 API를 지원하는 브라우저는 파일에 직접 저장하고, 지원하지 않으면 다운로드합니다.
다운로드 완료는 브라우저에서 확인해야 하며 변경 표시가 유지됩니다.
ZIP 출력과 작업 JSON 저장은 별개입니다. ZIP은 다시 편집하는 입력 형식이 아닙니다.

## 검사와 제한

- 고유 ID, 안전한 이미지 참조, 월드·섹터 크기
- 다각형 자기 교차·중복 점·넓이 0과 월드 밖 배치
- 입장 슬롯 수, 발 영역의 지형 포함과 슬롯 간 겹침
- 방의 인접 배치, 출구 방향, 경계 구간 내 출구·도착점
- 표시 이미지 중심과 워프 영역 일치, 목적지 참조와 양방향 출구
- 최초 입장 방에서 연결을 따라 도달 가능 여부
- 특수 오브젝트 ID·종류·표시 영역·이미지
- 출력 시 이미지의 실제 해석 여부와 원본 크기

발 영역은 가로 반경 32, 세로 반경 18의 타원입니다.
시작·도착 위치의 발 영역 전체가 한 이동 가능 다각형 안에 있어야 합니다.
워프 접촉은 꼭짓점·중점·평균점·9×9 표본으로 검사합니다. 전체 지형 경로 탐색은 수행하지 않습니다.

방 256개, 연결 1024개, 최대 인원 32명입니다.
방별 배경 이미지 64개, 영역 종류별 256개, 영역당 점 64개, 총 점 32768개입니다.
도착점·워프존·특수 오브젝트는 각각 256개, 오브젝트 속성은 JSON 객체당 20000자까지입니다.
섹터 수는 방별 65536개 이하이며 대소문자만 다른 ID·파일 경로는 중복입니다.
이미지당 15MB·한 변 8192px, 전체 base64 100MB, 작업 JSON 105MB, ZIP 128MB입니다.
많은 이미지나 복잡한 지형은 저장·검사·출력이 느려질 수 있습니다.

## 몬스터 배치

현재 기본 몬스터는 **Dummy (몬스터 Data ID 1)** 입니다. 이동·공격하지 않는 고정 표적입니다.
배치 ID는 방 안에서 고유하며 발 위치와 좌우 방향을 저장합니다.
배경 이미지에 합성하지 않고 별도의 `monsters` 목록으로 출력합니다.
출력 전 발 영역이 이동 가능 지역에 있는지, 워프존이나 플레이어 입장 슬롯과 겹치는지,
몬스터끼리 겹치는지 검사합니다. 방당 256개, 던전 전체 4096개까지 가능합니다.

## 게임 연동

1. 편집기의 **서버 던전 Data ID**를 TownServer `Data/DungeonCatalog.json`의 숫자 ID에 맞춥니다.
   예: ForgottenHall = 1. 몬스터 Data ID와 던전 Data ID는 서로 다른 값입니다.
2. 출력 ZIP을 서버 저장소 `ActionRPGServer/GameRoomServer/Data/Dungeons/<던전폴더>/`에 풉니다.
   그 폴더 바로 아래 `Dungeon.json`과 `Maps`가 있어야 합니다.
3. ZIP의 `Assets` 내용을 클라이언트 `ActionRPGClient/Assets/`에 같은 상대 경로로 복사합니다.
4. 서버·클라이언트를 다시 빌드하고 서버를 재시작합니다. 이미 빌드한 실행 파일을 사용한다면
   실행 파일 옆 서버 `Data/Dungeons`, 클라이언트 `Assets`에 직접 설치합니다.

서버는 시작 시 던전 파일을 검사하며 설치되지 않거나 잘못된 던전의 입장은 실패합니다.
던전 생성 때 배치된 몬스터마다 instance ID와 초기 HP 100을 생성합니다.
인증된 파티원들에게 같은 방 구성과 몬스터 정보를 전달하고, 클라이언트는 현재 방의 개체를 표시합니다.
다른 방에서 돌아오면 기존 개체를 유지합니다. 이동·게이트 전환은 서버에서 판정합니다.
이동 속도는 서버 플레이어 상태의 기본값과 클라이언트 Character에서 관리하며 방 JSON에는 포함하지 않습니다.
현재 단계에는 Dummy AI·공격·드랍·전투 판정과 파티원 위치 동기화가 포함되지 않습니다.
특수 오브젝트는 장식 이미지로 표시되며 상호작용과 미니맵 HUD는 후속 작업입니다.
ZIP이 게임에 자동 설치되지는 않습니다.

던전 JSON 총량은 3.5MB, 개별 JSON 파일은 4MB 이하입니다.
이미지는 클라이언트에 설치하며 네트워크로 전송하지 않습니다.
큰 던전의 최초 데이터 수신과 많은 몬스터의 화면 표시는 시간이 걸릴 수 있습니다.
