# Dungeon Map Editor

## 실행

이 폴더의 `index.html`을 Edge 또는 Chrome에서 엽니다. 인터넷, npm 설치, 별도 서버가 필요하지 않습니다.
처음에는 빈 던전으로 시작합니다.

Visual Studio의 `DungeonEditor` 프로젝트를 빌드하면
`artifacts/bin/x64/Debug/DungeonEditor.exe`로도 열 수 있습니다.
실행 파일은 같은 출력 폴더의 `DungeonEditor/index.html`을 기본 HTML 연결 프로그램으로 엽니다.
HTML이 텍스트 편집기에 연결되어 있다면 브라우저에서 직접 여세요.

## 기본 작업 순서

1. 왼쪽 **＋**로 방을 추가하고 ID·이름을 정합니다. 던전 속성에서 최초 입장 방과 최대 인원을 지정합니다.
2. **방 구성** 화면에서 방을 드래그해 미니맵 위치를 정합니다. 첫 방을 선택하고 **방 연결**을 누른 뒤 목적지 방을 클릭합니다.
   기본 연결은 양방향입니다. 연결 선을 선택하면 양방향 여부를 바꿀 수 있습니다.
3. 방을 더블 클릭하거나 **방 내부**를 누릅니다. **이미지 추가**로 배경을 넣고 위치·크기를 수정합니다.
   **이미지에 월드 영역 맞춤**으로 방의 표시 영역을 배경 전체에 맞추거나 경계를 직접 입력합니다.
4. **이동 가능 W** / **진입 불가 B**로 다각형 영역을 그립니다. 좌클릭으로 점을 추가하고 Enter 또는 **영역 완성**을 누릅니다.
5. 최초 입장 방에서 **입장 위치 P**로 최대 인원만큼 발 위치를 지정합니다.
   슬롯은 생성 순서로 배정할 수 있도록 `Dungeon.json`에 저장됩니다.
6. 모든 방에 **워프 도착점 E**를 배치하고 기본 도착점을 선택합니다. 여러 도착점을 만들 수 있습니다.
7. **워프존 Z**로 출발 영역을 그리고 해당 연결과 목적지 도착점을 선택합니다.
   목적지 방은 연결의 반대편 방으로 정해집니다. 양방향 연결은 양쪽 방에 워프존을 만들어야 합니다.
8. **작업 저장**으로 편집 가능한 JSON을 저장합니다. **정적 검사**를 확인하고 **던전 · 미니맵 출력**으로 게임용 ZIP을 내보냅니다.

### 방 배치 예

| 방 ID | 미니맵 열 X | 미니맵 행 Y | 연결 |
| --- | ---: | ---: | --- |
| A | 0 | 0 | A–B |
| B | 1 | 0 | B–C |
| C | 2 | 0 | C–D |
| D | 3 | 0 | D–E |
| E | 3 | 1 | E–Boss |
| Boss | 4 | 1 | 보스 방 |

왼쪽 자동 미니맵과 출력 미니맵 모두 이 배치를 사용합니다.
연결은 순환할 수 있고, 단방향 연결은 화살표로 표시합니다.
미니맵의 방을 클릭하면 그 방의 내부 편집 화면으로 이동합니다.

## 편집 조작

- 선택 모드에서 이미지, 입장 위치, 도착점, 영역 전체를 드래그합니다.
- 영역을 선택한 뒤 꼭짓점을 드래그하면 모양을 수정할 수 있습니다.
- 겹친 요소는 왼쪽 **방의 요소** 목록에서 선택합니다. 오른쪽에서 정확한 좌표를 입력할 수 있습니다.
- 가운데 버튼 또는 Space+좌클릭 드래그: 화면 이동
- 마우스 휠: 커서 위치를 중심으로 확대·축소
- F / 전체 보기: 현재 방 또는 전체 방 배치 맞춤
- V: 선택, W: 이동 가능, B: 진입 불가, P: 입장 위치, E: 도착점, Z: 워프존
- Enter: 영역 완성, Backspace: 마지막 꼭짓점 취소, Esc: 작성 중인 영역·연결 취소
- Delete: 선택 요소 삭제, Ctrl+S: 작업 저장

방 복제는 배경·지형·입장 위치·도착점을 복사합니다. 연결과 워프존은 새 방에서 지정합니다.
방 삭제는 관련 연결·워프존도 삭제합니다. 입장 방을 삭제하면 입장 방을 다시 지정해야 합니다.
도착점 삭제로 남은 목적지 참조는 정적 검사에서 오류로 표시합니다.

## 저장과 출력

**작업 JSON** (`*.dungeon-project.json`):

- 편집용 `schemaVersion: 1` 문서입니다.
- `rooms`에 월드 영역·배경·지형·입장 위치·도착점·워프존을 보관합니다.
- `connections`에 방 사이 방향을, `layout`에 미니맵 격자 좌표를 보관합니다.
- `assets`에 원본 이미지의 base64 데이터를 포함합니다. 원본 파일이 없어도 다시 편집할 수 있습니다.
- 미완성 문서나 빈 던전도 저장할 수 있습니다. 아직 완성하지 않은 다각형은 완성 또는 취소해야 합니다.

**출력 ZIP**:

```text
Dungeon.json                          던전 구성, 입장 슬롯, 방 연결, 미니맵 좌표
Maps/<DungeonId>_<RoomId>.json         마을 맵과 동일한 version 3 방별 맵 형식
Assets/Images/Dungeons/<DungeonId>_*   사용한 배경 이미지 파일
Minimap.svg                           배치·연결에서 자동 생성한 미니맵
Minimap.png                           투명 배경 미니맵
```

각 방의 맵에는 `world`, `images`, `walkablePolygons`, `blockedPolygons`,
`spawn`, `entryPoints`와 `transitionZones`가 들어갑니다.
워프는 `MapTransfer`의 `targetMapId`와 `targetEntryPointId`로 출력됩니다.
입장 방의 기본 `spawn`은 첫 파티원 입장 위치, 나머지 방은 기본 워프 도착점입니다.
이미지 경로는 실행 폴더의 `Assets` 기준 상대 경로입니다.

`Dungeon.json`의 `minimap.rooms`에는 각 방의 사각형과 중심 좌표가 들어갑니다.
게임에서 현재 방 ID에 해당하는 중심 좌표로 표시를 그릴 수 있습니다.
미니맵의 최대 한 변은 4096px이며 배치가 넓으면 전체가 비례 축소됩니다.
방 이름은 전체 데이터에 유지하고 작은 미니맵의 표시는 ID의 앞 12자를 사용합니다.

브라우저가 파일 선택·쓰기 API를 지원하면 선택한 파일에 직접 저장합니다.
지원하지 않으면 다운로드로 저장하며 브라우저에서 다운로드 완료를 확인해야 합니다.
다운로드 방식에서는 실제 저장 완료를 확인할 수 없어 변경 표시가 유지됩니다.
ZIP 출력은 작업 JSON 저장과 별개입니다. ZIP은 다시 편집하는 입력 형식이 아닙니다.

## 정적 검사

출력은 오류가 없어야 진행할 수 있습니다. 경고는 확인할 수 있도록 표시합니다.

- 고유한 ID와 안전한 출력 경로, 올바른 월드 크기·속도·이미지 참조
- 겹치지 않는 미니맵 격자 위치
- 자기 교차·중복 꼭짓점·넓이 0인 다각형과 월드 밖 영역
- 최대 인원만큼 최초 입장 슬롯 배치, 슬롯끼리 발 영역 겹침
- 입장·도착점의 발 영역이 한 이동 가능 다각형 안에 있고 진입 불가 영역과 겹치지 않는지
- 워프 목적지 방·도착점, 연결 방향, 양방향 연결의 양쪽 워프존
- 최초 입장 방에서 연결을 따라 도달할 수 있는지 (순환 허용)
- 이동 가능한 워프 접촉 지점, 도착 위치가 워프존 안에 있는지
- 출력 전에 이미지 실제 해석 여부와 원본 크기

발 영역은 현재 캐릭터 기준 타원(가로 반경 32, 세로 반경 18)입니다.
여러 이동 가능 영역이 맞닿아 있어도 시작 위치의 타원 전체가 한 영역에 들어가도록 배치하세요.
워프 접촉 검사는 꼭짓점·변의 중점·평균점·9×9 표본을 사용합니다.
좁거나 복잡한 워프존에서는 접촉점을 찾지 못할 수 있으므로 영역을 넓혀 주세요.
전체 지형의 경로 탐색이나 플레이 가능한 던전인지에 대한 판정은 수행하지 않습니다.

## 제한과 게임 연동 범위

- 방 256개, 연결 1024개, 최대 인원 32명
- 방별 이미지 64개, 영역 종류별 256개, 영역당 꼭짓점 64개
- 방별 전체 꼭짓점 32768개, 도착점·워프존 각각 256개
- 방별 섹터 수 65536개 이하, 대소문자만 다른 ID·파일 경로는 중복으로 처리
- 이미지당 15MB, 한 변 8192px, 전체 이미지 base64 100MB, 작업 JSON 105MB, 출력 ZIP 128MB
- 많은 이미지나 복잡한 영역을 한 번에 처리하면 저장·검사·출력이 느려질 수 있습니다.

현재 구현은 던전 정의 편집·저장·검사·맵과 미니맵 출력까지입니다.
서버의 던전 맵 로더, 입장 슬롯 배정, 방별 런타임 전환과 클라이언트 미니맵 HUD 연동은 별도 구현이 필요합니다.
특히 도착 직후 워프존 재발동을 막는 처리는 게임 런타임에서 적용해야 합니다.
출력 ZIP이 기존 게임에 자동 설치되거나 기존 마을 맵을 덮어쓰지는 않습니다.
